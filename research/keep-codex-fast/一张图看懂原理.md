## 关键数据结构

### SessionCandidate

```python
@dataclass
class SessionCandidate:
    size: int          # 会话目录大小（字节）
    thread_id: str     # UUID 格式线程 ID
    title: str         # 线程标题
    source: Path       # 原始 rollout 路径
    relative: Path     # 相对路径
    updated_at: int | None  # 更新时间戳
```

### ThreadMetadataRepair

```python
@dataclass
class ThreadMetadataRepair:
    thread_id: str
    old_title: str     # 修复前的完整标题
    new_title: str     # 修复后（截断至 120 字符）
    old_preview: str   # 修复前的完整预览
    new_preview: str   # 修复后（截断至 240 字符）
```

## 会话归档机制

```
sessions/2026/01/01/
└── rollout-2026-01-01T00-00-00-{thread_id}.jsonl
                                        │
                                        ▼
                    ┌────────────────────────────────────────┐
                    │  active_session_candidates()            │
                    │                                        │
                    │  1. 扫描 sessions/YYYY/MM/DD/ 目录      │
                    │  2. 读取 state_5.sqlite 中的 threads 表 │
                    │  3. 过滤条件：                          │
                    │     ✅ archived = 0                    │
                    │     ✅ 不是 pinned thread               │
                    │     ✅ updated_at < (now - days)       │
                    │     ✅ rollout 文件存在                 │
                    │  4. 返回 SessionCandidate 列表         │
                    └────────────────────┬───────────────────┘
                                         ▼
                    ┌────────────────────────────────────────┐
                    │  archive_sessions()                     │
                    │                                        │
                    │  if apply:                             │
                    │    1. 执行 SQL: UPDATE threads        │
                    │       SET archived=1,                 │
                    │           archived_at=now,             │
                    │           rollout_path='archived_...' │
                    │    2. 移动 rollout JSONL 到归档目录    │
                    │    3. 写入 restore 脚本                │
                    │  else:                                 │
                    │    仅报告候选数量和大小                  │
                    └────────────────────────────────────────┘
```

## 元数据修复机制

```
state_5.sqlite → threads 表
┌─────────────────────────────────────────────────┐
│  id            │ title (数百KB)                  │
│  first_user_message (数百KB)                     │
│  rollout_path  │ cwd        │ updated_at        │
└─────────────────────────────────────────────────┘
           │
           ▼
report_thread_metadata_bloat()
  → 统计: active_threads, total_title_chars, max_title_len
  → 报告: over_limit_count (标题>120, 预览>240)
           │
           ▼
repair_thread_metadata_bloat(apply=True, opt_in=True)
  → 仅在 --apply --repair-thread-metadata-bloat 时执行
  → 1. bounded_text(title, 120)  ← 截断标题
  → 2. bounded_text(preview, 240) ← 截断预览
  → 3. 追加到 session_index.jsonl（同步名称更新）
  → 4. 写入 thread-metadata-repairs.jsonl（恢复用）
  → 5. 写入 restore-thread-metadata.py
  ⚠️ rollout JSONL 内容不受影响
```

## 隐私保护机制

```
默认模式（--details 未指定）:
─────────────────────────────────────
输出: "codex_process_001"    替代: 实际进程路径
     "active_session_candidate_001" 替代: 线程 UUID

─────────────────────────────────────
--details 模式:
─────────────────────────────────────
输出: 原始线程 UUID、聊天标题、本地绝对路径
      ⚠️ 仅在诊断问题时使用
```

## 恢复机制

```
备份目录结构:
~/Documents/Codex/codex-backups/keep-codex-fast-{stamp}/
├── state_5.sqlite              # SQLite 数据库副本
├── config.toml                 # 配置文件副本
├── session_index.jsonl         # 会话索引
├── restore-sessions.py         # 恢复归档会话脚本
├── restore-thread-metadata.py  # 恢复元数据脚本
├── moved-sessions.jsonl       # 已移动会话清单
├── moved-worktrees.jsonl      # 已移动工作树清单
└── thread-metadata-repairs.jsonl  # 元数据修复记录
```

恢复原理：
1. `restore-sessions.py` 读取 `moved-sessions.jsonl`
2. 将 rollout JSONL 移回原始位置
3. 执行 SQL: `UPDATE threads SET archived=0, rollout_path=原始值`
4. `restore-thread-metadata.py` 读取 `thread-metadata-repairs.jsonl`，恢复原始 title/preview
