## 一、项目概述

keep-codex-fast 是专为 **Codex**（OpenAI 桌面 Agent）设计的本地状态维护工具。当 Codex 使用时间增长后，本地会话、工作树、日志、配置不断积累，系统开始变慢。本工具提供一套安全维护流程，在保留上下文的同时减少本地负担。

**核心理念**: Chats are for execution. Handoff docs are for memory. Archives are for history. Fresh threads are for speed.

---

## 二、核心设计原则

### 2.1 Handoffs First（交接优先）

归档旧会话前，先为重要仓库会话创建**交接文档**（Handoff Doc）和**重新激活提示语**（Reactivation Prompt），确保上下文可延续。

交接文档包含：
- 仓库路径和分支
- 当前目标
- 已完成的工作
- 涉及的文件
- 已运行的命令和测试
- 已知错误和警告
- 待决事项
- 约束、用户偏好、"勿动"区域
- 接下来 3-7 个具体步骤

### 2.2 Archive, Don't Delete（归档而非删除）

不永久删除任何内容，全部移入归档目录并附带恢复脚本。删除内容始终可恢复。

### 2.3 Inspect Before Mutate（先检查后变更）

默认只读报告模式，不写入任何文件。所有变更前先备份。

## 三、三种运行模式

| 模式 | 行为 | 适用场景 |
|------|------|----------|
| **Inspect**（默认） | 只读报告，不写任何文件 | 首次检查，隐私安全 |
| **Maintain**（`--apply`） | 备份→归档→迁移→规范化 | 确认无误后执行 |
| **Repair**（`--apply --repair-thread-metadata-bloat`） | 额外修剪线程标题/预览元数据 | 仅在元数据膨胀时 opt-in |

## 四、功能模块

| 模块 | 描述 |
|------|------|
| **会话归档** | 归档非置顶的旧会话（按天数阈值），自动跳过置顶会话 |
| **工作树迁移** | 将长期不活跃的工作树移出热路径至 `~/.codex/archived_worktrees/` |
| **日志轮转** | 压缩过大的 `logs_2.sqlite*` 文件至 `~/.codex/archived_logs/` |
| **路径规范化** | 修正 Windows `\\?\C:\...` 扩展路径在 SQLite 中的存储 |
| **配置剪枝** | 移除 `config.toml` 中指向已不存在或临时目录的项目引用 |
| **元数据压缩** | （可选）修复 SQLite 中线程标题和预览字段的异常膨胀（默认不执行） |
| **进程报告** | 报告重量级 Node 进程（不杀死） |

## 六、安全性设计

1. **隐私保护**: 默认模式不输出原始线程ID、聊天标题、本地路径
2. **备份先行**: 所有变更前自动备份到 `~/Documents/Codex/codex-backups/`
3. **恢复脚本**: 每个归档操作附带 `restore-*.py` 脚本
4. **防误删**: 永久删除被禁止，删除内容可恢复
5. **元数据修复分离**: 元数据压缩不在常规 apply 中自动执行，需明确 opt-in
6. **运行时保护**: 检测到 Codex 正在运行时拒绝应用变更

## 八、对 agent-harness 的参考价值

### 8.1 可迁移场景

为 agent-harness 编写类似的 `keep-claude-code-fast` 技能，维护 Claude Code 的本地状态。

### 8.2 Handoff 模式的普适性

"交接文档 + 重新激活提示语"理念适用于所有长时间运行的 Agent 会话：
- 项目交接时的上下文延续
- 归档旧会话后快速恢复工作状态
- 团队协作时的知识传递

### 8.3 维护理念迁移

这一理念可以迁移到任何 Agent 系统的状态管理。

### 8.4 标准库优先

保持依赖最小化，仅用 Python 标准库，降低使用门槛。
