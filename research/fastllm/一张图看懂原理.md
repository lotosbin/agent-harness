# 一张图看懂 fastllm 原理

## 1. 量化原理

```
原始权重 (FP16/BF16)
       │
       ▼
┌─────────────────────────────────────────────────────────────────┐
│                      量化流程                                    │
│                                                                 │
│  FP16:  1bit 符号 │ 5bit 指数 │ 10bit 尾数   = 16 bits         │
│  INT8:  1byte = -128 ~ +127                                    │
│  INT4:  1nibble = -8 ~ +7                                      │
│                                                                 │
│  ┌──────────────────────────────────────────────────────┐      │
│  │  GPTQ / AWQ 校准式量化 (权重量化)                      │      │
│  │  1. 收集校准数据 (代表性输入样本)                      │      │
│  │  2. 计算每层 Hessian 矩阵 (误差权重)                   │      │
│  │  3. 按重要性排序量化参数组                            │      │
│  │  4. 逐组量化，最小化重构误差                           │      │
│  └──────────────────────────────────────────────────────┘      │
│                                                                 │
│  ┌──────────────────────────────────────────────────────┐      │
│  │  INT4g (分组量化)                                     │      │
│  │  将权重按组划分 (如 128 个元素为一组)                   │      │
│  │  每组独立计算 scale + zero_point                       │      │
│  │  → 更精细的缩放因子 → 更高精度                         │      │
│  └──────────────────────────────────────────────────────┘      │
└─────────────────────────────────────────────────────────────────┘
       │
       │ 量化后
       ▼
  .flm 文件 (存储格式)
  ┌──────────────────────────────────────┐
  │ Header (版本号、模型配置)             │
  ├──────────────────────────────────────┤
  │ Vocab (词表)                         │
  ├──────────────────────────────────────┤
  │ Embedding 表 (已量化)                │
  ├──────────────────────────────────────┤
  │ Layer 0: QKV投影 | 量化参数           │
  │ Layer 0: Attention 输出投影 | 量化参数 │
  │ Layer 0: FFN | 量化参数               │
  │ ... (每个 Linear 层独立量化)          │
  ├──────────────────────────────────────┤
  │ Layer N: ...                         │
  └──────────────────────────────────────┘
```

## 2. Attention 原理

```
标准 MHA (Multi-Head Attention)
┌──────────────────────────────────────────────────────────────┐
│ Input X                                                    │
│    ↓                                                       │
│ Linear(Q), Linear(K), Linear(V) → Q, K, V (分头)          │
│    ↓                                                       │
│ Q @ K^T / sqrt(d_k)  →  Attention Scores                   │
│    ↓                                                       │
│ Softmax → Attention Weights                                │
│    ↓                                                       │
│ Weights @ V → 输出                                         │
└──────────────────────────────────────────────────────────────┘

fastllm 优化点:
┌──────────────────────────────────────────────────────────────┐
│ 1. FlashAttention 风格                2. MLA (DeepSeek)     │
│    分块计算 + 积分                       低秩键值压缩        │
│    避免完整 Attention Matrix           ┌──────────────────┐ │
│    显存 O(N²) → O(N)                   │ K_Compressed =   │ │
│    ┌────────┐                           │   W_K @ X        │ │
│    │ Block1 │ → 在线 softmax 更新       │                  │ │
│    │ Block2 │ → 在线 softmax 更新       │ c_K = silu(W_K'  │ │
│    │ Block3 │ → 在线 softmax 更新       │         @ X)     │ │
│    └────────┘                           │                  │ │
│                                         │ Q_Compressed =   │ │
│ 3. 动态 Batch 合并                       │   W_Q @ X        │ │
│    不同长度请求 padding 后批量推理        │                  │ │
│    请求1: [A B C D] → 4 tokens          │ c_Q = silu(W_Q'  │ │
│    请求2: [E F G H I J] → 6 tokens  →   │         @ X)     │ │
│    拼接: [A B C D | pad] [E F G H I J]  │                  │ │
│         batch_size=2, max_len=6          │ 解压时用 c_K 解   │ │
│                                         │   还原 K/V 用于   │ │
│ 4. KV Cache 流式输出                     │   Attention      │ │
│    生成 token 后立即推送                 └──────────────────┘ │
│    无需等待完整生成完成                  减少 KV Cache 显存占用
└──────────────────────────────────────────────────────────────┘
```

## 3. MOE 混合推理原理

```
┌──────────────────────────────────────────────────────────────────┐
│                    MOE 层 Forward 流程                           │
│                                                                  │
│  Input X                                                          │
│     ↓                                                             │
│ ┌───────────────────────────┐                                    │
│ │ Router (线性层)            │ → 预测每个 Expert 的激活概率      │
│ │  W_router @ X             │    shape: [batch, seq_len, n_experts]│
│ │  Softmax(..., dim=-1)     │                                    │
│ └─────────────┬─────────────┘                                    │
│               ↓                                                  │
│ ┌───────────────────────────┐                                    │
│ │ Top-K 选择                  │ → 选取概率最高的 K 个 Expert       │
│ │  DeepSeek-R1: K=8          │   每个 token 仅激活 8/256 个专家   │
│ └─────────────┬───────────────┘                                    │
│               ↓                                                   │
│               ↓ 分发到不同设备                                    │
│     ┌─────────┴─────────┐                                        │
│     ↓                   ↓                                        │
│ ┌─────────┐      ┌─────────────┐                                 │
│ │Shared   │      │ Routed      │                                 │
│ │Expert   │      │ Experts 1-8 │                                 │
│ │(GPU)    │      │ (CPU/NUMA)  │  ← MOE 层通常放 CPU            │
│ │所有token │      │ 每token不同  │     减少 GPU 显存压力          │
│ │共享计算  │      │ 动态调度     │                                 │
│ └────┬────┘      └──────┬──────┘                                 │
│      │                  │                                         │
│      └──────┬───────────┘                                        │
│             ↓                                                    │
│    加权求和:  Σ(topk_probs[i] * expert_i_output)                 │
│             ↓                                                    │
│         Output X'                                                 │
│                                                                  │
│ 显存节省: 稠密层 1T 参数 → MOE 层仅激活 20B (DeepSeek-R1)       │
│           671B 模型在 10G+ 显存即可推理                          │
└──────────────────────────────────────────────────────────────────┘
```

## 4. 多卡张量并行原理

```
                         输入 X
                            │
            ┌───────────────┼───────────────┐
            ↓               ↓               ↓
         Card 0          Card 1          Card 2
       ┌────────┐      ┌────────┐      ┌────────┐
       │ QKV_0  │      │ QKV_1  │      │ QKV_2  │
       │ KV_0   │      │ KV_1   │      │ KV_2   │
       │ Attn_0 │  ──→ │ Attn_1 │  ──→ │ Attn_2 │  ← AllReduce
       │ FFN_0  │      │ FFN_1  │      │ FFN_2  │
       │ Out_0  │      │ Out_1  │      │ Out_2  │
       └────────┘      └────────┘      └────────┘
            │               │               │
            └───────────────┼───────────────┘
                            ↓
                    聚合输出 (AllReduce)

每张卡计算 1/N 的注意力头和 FFN 权重
通信开销: Attention 后的 AllReduce (all-reduce 带宽 = N * 单卡带宽)
fastllm 特色: 支持奇数卡 (3/5/7...) 及 GPU+CPU 混合并行
  --device multicuda:0,1,2          # 纯 GPU
  --device multicuda:0,cpu          # GPU + CPU (CPU 承担部分计算)
  --device multicuda:0:4,1:5,cpu:1  # 按比例分配计算量
```

## 5. 模型转换流程

```
HuggingFace 模型 (.safetensors)
        │
        ▼
┌─────────────────────────────────────────────────────────┐
│  torch2flm.py (Python)                                  │
│                                                         │
│  1. 读取 config.json → 解析模型结构、词表、分词器      │
│  2. 遍历每个权重文件 (key -> value)                      │
│  3. 对权重进行量化 (可选: --dtype int4)                 │
│  4. 写入 .flm 二进制文件                                 │
│     - 头部: 版本号、模型类型、量化配置                   │
│     - 词表: token -> id 映射                             │
│     - 分词器: sentencepiece model (如适用)              │
│     - 权重: 量化后的参数 + scale/zero_point              │
│  5. (可选) 预计算并缓存一些中间结果                       │
└─────────────────────────────────────────────────────────┘
        │
        ▼
  .flm 文件 (fastllm 自有格式)
        │
        │ ftllm server (C++ 运行时)
        ▼
┌─────────────────────────────────────────────────────────┐
│  FastLLM C++ Runtime                                     │
│                                                         │
│  1. mmap .flm 文件 → 零拷贝加载权重                       │
│  2. 根据模型类型实例化对应模型类 (ChatGLM / Qwen / ...)  │
│  3. 构建计算图 (Ops 注册到 Device)                       │
│  4. 推理请求到达 → Tokenizer 编码 → Forward → 解码     │
└─────────────────────────────────────────────────────────┘

pip install ftllm 方式: 直接在线量化，无需预先转换
.ftllm export 方式:  预转换量化，推理时加载更快
```
