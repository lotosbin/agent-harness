# fastllm 研究报告

## 一、项目概述

**fastllm** 是由 [@ztxz16](https://github.com/ztxz16/fastllm) 开发的纯 C++ 高性能大模型推理库，采用自有底层算子替代 PyTorch，实现了无第三方依赖的跨平台部署。截至 2026-05-09，项目在 GitHub 拥有 **4,449** Stars、448 Forks、282 Open Issues，Apache License 2.0 开源，最近活跃更新（2026-05-09）。

### 定位

fastllm 介于 llama.cpp（极致轻量、边缘优先）和 vLLM（企业级高并发）之间，在国产硬件支持和 MOE 模型混合推理方面有独特优势。

---

## 二、因（Causality）——为何存在

### 2.1 市场需求

- 2023 年 ChatGLM-6B 等 6-7B 模型开源后，在消费级硬件上本地部署大模型的需求爆发
- 当时主流推理方案依赖 PyTorch，体积庞大、依赖复杂，难以在移动端/嵌入式设备部署
- llama.cpp 虽轻量，但当时对中文模型和多模态支持不完善，国产硬件（昇腾、沐曦等）几乎无支持

### 2.2 技术驱动

- C++ 自有算子可精细控制内存布局、指令级并行（SIMD/NEON/AVX/CUDA），实现比 Python binding 更低的推理延迟
- 前后端分离架构使添加新硬件支持成本极低——只需实现 Device 抽象层
- MOE（Mixture of Experts）架构（如 DeepSeek R1 671B）因专家数量庞大，单卡显存不足，需要 GPU+CPU 混合推理方案

### 2.3 演进轨迹

| 时间 | 里程碑 |
|------|--------|
| 2023-05 | 项目启动，支持 ChatGLM、LLAMA、MOSS 系列，CPU+移动端推理 |
| 2023-12 | ChatGLM3 支持，流式输出、WebUI、API Server |
| 2024 | CUDA 支持、INT8/INT4 量化、PEFT/LoRA 支持 |
| 2025 | MOE 模型支持（DeepSeek R1、Qwen-MOE）、张量并行、混合推理 |
| 2026-04 | DeepSeek-V4 支持、动态量化、GGUF 格式读取、Qwen3 支持 |
| 2026-05 | ROCm（AMD GPU）、昇腾 NPU 等更多国产硬件支持 |

## 四、体（Substance）——技术架构

### 4.1 核心数据结构

```
Data（类比 PyTorch Tensor）
├── dataType: FLOAT32 | INT8 | INT4 | BF16 | FP16 | FP8 | ...
├── weightType: 权重类型标识
├── shape: 张量形状
├── device: 所在设备 (CPU/CUDA/...)
├── lockInCPU: 是否锁在 CPU
└── zeroCopy: 是否零拷贝
```

### 4.2 Device 抽象层（前后端分离核心）

fastllm 采用策略模式实现 Device 抽象，每种硬件只需实现统一接口：

- `CpuDevice`: ARM NEON / x86 AVX 加速
- `CudaDevice`: NVIDIA CUDA 加速
- `RocmDevice`: AMD ROCm 加速
- `昇腾Device`: 华为昇腾 NPU
- `NumaDevice`: 多路 NUMA 节点加速
- `MultiCudaDevice`: 多卡张量并行

### 4.3 算子实现

- **Attention**: FlashInfer 风格实现，支持 MLA（Multi-head Latent Attention）
- **MOE 调度**: 参考 KTransformers 动态调度 + Lvllm NUMA 优化
- **量化 Kernel**: 借鉴 llama.cpp/ik_llama.cpp 的 GGML 量化方法
- **数据并行**: 针对 DeepSeek 模型优化的数据并行注意力机制

### 4.4 模型加载流程

```
HuggingFace 模型 (safetensors)
    → torch2flm.py 转换工具
    → .flm 格式（自有二进制）
    → C++ 运行时加载推理
```

支持在线量化：读取原始模型时实时量化（INT4/INT8），或通过 `ftllm export` 预导出量化模型。

### 4.5 目录结构

```
fastllm/
├── include/fastllm.h       # 核心头文件（Data类、Device抽象、模型基类）
├── src/
│   ├── models/             # 各模型实现（chatglm.cpp, qwen.cpp, deepseek.cpp...）
│   ├── devices/            # Device 实现（cpu, cuda, rocm...）
│   └── ops/                # 底层算子（matmul, attention, softmax...）
├── tools/
│   ├── fastllm_pytools/   # Python 工具（torch2flm.py 模型转换）
│   └── webui.cpp          # WebUI 入口
├── pyfastllm/              # PyBind Python 绑定
├── docs/                  # 文档（deepseek部署、qwen3、FAQ等）
└── CMakeLists.txt         # 构建配置
```

## 五、用（Application）——使用指南

### 5.1 pip 一键安装（推荐）

```bash
# Linux + NVIDIA GPU
pip install ftllm -U

# Linux + AMD GPU（需先装 ROCm 6.3.3）
pip install ftllm-rocm -U

# Windows + NVIDIA GPU（先装依赖）
pip install https://www.modelscope.cn/models/huangyuyang/fastllmdepend-windows/resolve/master/ftllmdepend-0.0.0.2-py3-none-win_amd64.whl
pip install ftllm -U
```

### 5.2 源码编译

```bash
git clone https://github.com/ztxz16/fastllm.git
cd fastllm
bash install.sh -DUSE_CUDA=ON -D CMAKE_CUDA_COMPILER=$(which nvcc)
```

### 5.3 三种运行方式

```bash
# 命令行对话
ftllm run Qwen/Qwen3-0.6B

# WebUI
ftllm webui Qwen/Qwen3-0.6B

# OpenAI 风格 API Server
ftllm server Qwen/Qwen3-0.6B --port 8080
```

### 5.4 常用参数

| 参数 | 说明 | 示例 |
|------|------|------|
| `--dtype` | 推理精度 | `--dtype int4` |
| `--moe_dtype` | MOE 层精度 | `--moe_dtype int4` |
| `--device` | 运行设备 | `--device multicuda:0,1` |
| `--moe_device` | MOE 层设备 | `--moe_device cpu` |
| `-t` | CPU 线程数 | `-t 27` |
| `--port` | API 端口 | `--port 8080` |
| `--think` | 强制启用思考模式 | `--think` |
| `--dtype_config` | 动态量化配置 | `--dtype_config config.json` |

### 5.5 DeepSeek R1 671B 单卡部署示例

```bash
# FP8 精度，单并发 ~20 tokens/s
ftllm server deepseek-ai/DeepSeek-R1 --dtype fp8 --device cuda

# INT4 精度，单并发 ~30 tokens/s，多并发可达 60+ tokens/s
ftllm server deepseek-ai/DeepSeek-R1 --dtype int4 --device cuda --moe_device cpu

# 多卡张量并行
ftllm server deepseek-ai/DeepSeek-R1 --dtype fp8 --device multicuda:0,1
```

### 5.6 模型导出与本地化

```bash
# 下载模型
ftllm download deepseek-ai/DeepSeek-R1

# 导出量化模型（避免每次在线量化）
ftllm export /mnt/DeepSeek-R1 -o /mnt/DeepSeek-R1-INT4 --dtype int4 -t 16

# 加载导出后的模型
ftllm server /mnt/DeepSeek-R1-INT4
```

### 5.7 Python API

```python
import ftllm

# 加载模型
model = ftllm.load("/path/to/model", dtype="int4", device="cuda")

# 对话
response = model.chat("你好，请介绍一下自己")
print(response)
```

## 六、洞（Insights）——深度洞察

### 6.1 核心优势

1. **零依赖 C++ 运行时**: 无 PyTorch 依赖，部署包极小，可直接在 Android NDK 编译运行。llama.cpp 是类似设计，但 fastllm 在国产硬件支持和 MOE 混合推理上更完善。
2. **MOE 混合推理标杆**: DeepSeek R1 671B 仅需 10G+ 显存任意显卡即可推理，通过 GPU 处理稠密层 + CPU 处理 MOE 层，突破了单卡显存限制。这是 fastllm 最具差异化的能力。
3. **国产硬件优先**: 昇腾 NPU、天数、沐曦、燧原等国产卡的直接支持在国内开源项目中罕见，对信创场景有实际价值。
4. **安装体验最优**: `pip install ftllm` 一条命令完成安装，相比 llama.cpp 编译 + 模型转换的繁琐流程，用户门槛极低。
5. **张量并行灵活性**: 支持 3/5/7 奇数卡并行，以及 GPU+CPU 混合并行，可充分利用异构硬件。

### 6.2 现存局限

1. **社区规模**: 4.4k Stars 相比 llama.cpp (60k) 和 vLLM (50k) 差距显著，文档和社区支持相对薄弱，英文资料稀少。
2. **Python 生态**: 虽然提供 PyBind 绑定，但远不如 vLLM 与 HuggingFace Transformers 的深度集成。
3. **FFN/Attention 算子优化**: 部分实现参考了 FlashInfer 等项目，自有算子的底层优化深度可能不及 TensorRT-LLM。
4. **Windows 支持受限**: 仅支持 NVIDIA GPU，无 AMD/昇腾等选项。
5. **生产级特性**: 缺少 vLLM 的 PagedAttention 级别的显存管理精细度、prefix caching 优化深度，以及 SGLang 的结构化输出加速。
6. **FFI 调用开销**: Python API 通过 PyBind 调用 C++，每次 token 生成都有跨语言开销，高频调用场景下需注意。

### 6.3 适用场景

| 推荐 | 不推荐 |
|------|--------|
| 移动端/嵌入式部署（Android） | 超大规模在线服务（>100 QPS） |
| 国产硬件（昇腾/沐曦）部署 | 需要 prefix caching 的高并发推理 |
| DeepSeek R1 等 MOE 模型本地部署 | 需要极致量化（<INT4，如 GPTQ 2-bit） |
| 多卡异构环境（GPU+CPU 混合） | 需要 TensorRT-LLM 级别的极致性能 |
| 快速原型验证（pip 一键部署） | 需要完善监控/可观测性集成的生产环境 |
| 个人开发者本地使用 | 需要多模态模型支持 |

### 6.4 技术风险

1. **维护风险**: 核心开发者单一（ztxz16），项目健康度依赖个人投入。282 个 open issues 积累，长期维护压力存在。
2. **协议兼容性**: GGUF 格式支持仍处于部分读取阶段（需 `--ori` 参数指定源模型），可能遇到边缘 case。
3. **量化精度**: 动态量化配置（`dtype_config`）需要手动调参，非专业用户可能难以获得最优精度/速度平衡。
4. **依赖更新滞后**: 参考 PyTorch/Transformers 的实现逻辑，可能在新模型架构发布后需要一定时间适配。

### 6.5 未来关注点

- DeepSeek-V4 (1M 上下文) 的完整支持进展
- 与主流 Agent 框架（LangChain、LlamaIndex）的集成深度
- 国产芯片驱动更新节奏
- 与 llama.cpp 在量化方法上的互相借鉴
