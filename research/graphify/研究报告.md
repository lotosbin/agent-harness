# graphify 研究报告

## 一、项目概述

**graphify** 是由 [safishamsi](https://github.com/safishamsi) 开发的代码库知识图谱提取工具，通过 Tree-sitter AST + LLM 语义理解，将代码/文档/PDF/视频转换为可查询的交互式知识图谱。截至 2026-05-09，项目版本 v0.7.13，Python 实现（1.17MB），支持 16+ AI 编程助手平台集成。

### 定位

graphify 是**全局结构感知层**，而非 RAG 替代品——让 AI 在回答任何问题前先理解代码拓扑，解决大型代码库中上下文缺失的问题。

---

## 二、因（Causality）——为何存在

### 2.1 市场需求

- AI 编程助手（Claude Code / Cursor 等）在大型代码库中缺乏全局上下文，每次会话从零开始
- 无法感知跨文件的深层模块关联，回答浮于表面
- 现有方案（grep/RAG）无法揭示代码拓扑结构

### 2.2 技术驱动

- **Tree-sitter AST 解析**成熟，本地提取代码结构零成本
- **Leiden 聚类算法**成熟，无需独立 embeddings 或向量数据库
- **LLM** 具备从文档/PDF 中推理关系的能力
- AI 编程助手生态（Claude Code/Cursor/VS Code Copilot）广泛覆盖

### 2.3 演进轨迹

| 时间 | 里程碑 |
|------|--------|
| v1-v3 | 基础代码图谱提取，Claude Code 集成 |
| v4 | 扩展多平台支持（Cursor/VS Code/Gemini CLI/Aider） |
| v5 | 增加视频转录（faster-whisper）、文档语义提取 |
| v6 | MCP Server、Neo4j 导出、Obsidian Vault 生成 |
| v7 (2026-05) | callflow-html 架构图生成、Ollama VRAM 修复 |

## 四、体（Substance）——技术架构

### 4.1 处理管线（三阶段）

```
输入文件
  │
  ├─> 阶段1: 代码结构提取（免费）
  │     Tree-sitter AST 解析，提取类/函数/导入/调用图
  │     29+ 语言本地处理，零 API 调用
  │
  ├─> 阶段2: 媒体转录（免费）
  │     faster-whisper 本地转录视频/音频
  │     用代码图谱中的关键概念作为 prompt
  │
  └─> 阶段3: 文档语义提取（消耗 Token）
        Claude subagent 并行处理 Markdown/PDF/图片
        输出 JSON 片段合并为最终图谱
```

### 4.2 置信度体系

| 标签 | 含义 | 置信度 |
|------|------|--------|
| EXTRACTED | 源码直接证据（import/调用链） | 1.0 |
| INFERRED | LLM 推理，基于评分规则 | 0.95 ~ 0.55 |
| AMBIGUOUS | 不确定，需人工审查 | — |

INFERRED 评分规则示例：
- 0.95：显式跨文件引用 + 唯一合理目标
- 0.65：命名相似性匹配

### 4.3 聚类算法

Leiden 算法基于边密度聚类，不依赖独立 embeddings 或向量数据库。已有 `semantically_similar_to` 语义相似边可直接用于聚类。

### 4.4 性能数据

- 52 个混合文件（Karpathy 仓库 + 论文 + 图片）基准测试：**71.5x Token 节省**（相比直接读文件）
- SHA256 内容哈希跳过未变更文件，支持增量更新
- ProcessPoolExecutor 并行提取

### 4.5 目录结构

```
graphify/
├── extract.py      # 代码/文档解析入口
├── build.py        # NetworkX 图谱构建
├── cluster.py      # Leiden 聚类
├── analyze.py      # 节点分析（God nodes, 意外连接）
├── report.py       # GRAPH_REPORT.md 生成
├── export.py       # 多格式导出（HTML/SVG/Neo4j/Obsidian）
├── serve.py        # MCP stdio server
├── detect.py       # 文件发现，CODE_EXTENSIONS 配置
├── cache.py        # 语义缓存
├── security.py     # URL/路径/标签验证
└── validate.py     # schema 验证
```

## 五、用（Application）——使用指南

### 5.1 安装

```bash
# Python 3.10+
pip install graphifyy && graphify install

# 或使用 uv（推荐）
uv tool install graphifyy && graphify install

# Claude Code
graphify install
```

### 5.2 核心命令

```bash
# 构建当前目录图谱（主要用法）
/graphify .

# 指定目录
/graphify ./src --mode deep

# 增量更新（仅处理变更文件）
/graphify . --update

# 仅聚类（跳过提取）
/graphify . --cluster-only

# 跳过 HTML 生成
/graphify . --no-viz

# 构建调用流架构图
graphify export callflow-html

# 图谱查询
graphify query "what connects auth to the database?"
graphify path "UserService" "DatabasePool"
graphify explain "RateLimiter"

# 启动 MCP 服务（供 Agent 工具调用）
/graphify . --mcp
```

### 5.3 忽略文件

创建 `.graphifyignore`（与 `.gitignore` 语法相同）：

```
# .graphifyignore
node_modules/
dist/
*.generated.py
!src/
```

### 5.4 平台特定安装

| 平台 | 命令 |
|------|------|
| Claude Code | `graphify install` |
| Cursor | `graphify cursor install` |
| VS Code Copilot | `graphify vscode install` |
| Aider | `graphify install --platform aider` |
| Trae | `graphify install --platform trae` |
| Gemini CLI | `graphify install --platform gemini` |
| Hermes | `graphify install --platform hermes` |
| Kimi Code | `graphify install --platform kimi` |

### 5.5 文档提取后端配置

```bash
# Claude
ANTHROPIC_API_KEY=sk-... graphify extract ./docs --backend claude

# Gemini
GEMINI_API_KEY=... graphify extract ./docs --backend gemini

# Kimi
MOONSHOT_API_KEY=... graphify extract ./docs --backend kimi

# Ollama（本地，无需 API key）
OLLAMA_BASE_URL=http://localhost:11434 graphify extract ./docs --backend ollama

# AWS Bedrock（无 API key，使用 IAM）
graphify extract ./docs --backend bedrock
```

### 5.6 团队协作

```bash
# 1. 团队一人构建图谱并提交到 git
/graphify .
git add graphify-out/
git commit -m "Add knowledge graph"

# 2. 其他成员拉取后，助手自动读取 GRAPH_REPORT.md

# 3. 设置自动重建钩子
graphify hook install

# 4. 增量更新
/graphify . --update
```

## 六、洞（Insights）——深度洞察

### 6.1 核心优势

1. **本地免费提取**：代码结构完全本地 Tree-sitter 解析，零 Token 消耗，隐私安全
2. **多模态覆盖**：除代码外还处理文档/PDF/视频，覆盖研究场景的核心信息来源
3. **平台广泛**：支持 16+ 主流 AI 编程助手，适用范围广
4. **Token 节省**：71.5x 节省，显著降低 AI 推理成本
5. **团队协作**：图谱文件可提交 git，团队成员拉取即用
6. **MCP 服务**：暴露为 MCP server，Agent 可通过工具调用访问图谱

### 6.2 现存局限

1. **文档提取依赖 AI API**：需要配置 API Key（Claude/Gemini/Kimi/Ollama），无完全免费方案
2. **中文支持待验证**：README 有简体中文翻译版，但工具对中文代码/文档提取质量需实测
3. **大型代码库性能**：万级文件以上需关注并行度和 Token 预算控制（`--max-workers 16`）
4. **商业化路径**：作者推广 Penpax 商业产品，存在商业转化可能（核心仍开源）
5. **研究 SOP 契合度**：作为辅助工具价值明确，但"因果体用"报告结构仍需人工判断

### 6.3 适用场景

| 推荐 | 不推荐 |
|------|--------|
| 大型开源项目的全局理解 | 小型脚本的快速调研 |
| 多模块架构的深层关联发现 | 单一文件的功能解释 |
| 团队共享代码库上下文 | 纯自然语言问答（非代码相关） |
| 研究报告的结构化输入补充 | 需完全离线运行的场景（文档处理需 API） |
| Agent 工具调用（图谱查询） | 需要极深 AST 语义的场景 |

### 6.4 技术风险

1. **API 依赖**：文档处理依赖外部 API，网络/密钥问题会导致失败
2. **Ollama VRAM**：v0.7.13 修复了 Ollama VRAM 问题，但本地模型仍需注意显存
3. **版本兼容性**：Graphify Labs 商业产品与开源版本可能存在功能分化
4. **图谱一致性**：大型项目增量更新时，图谱可能因文件删除/重命名产生孤立节点
