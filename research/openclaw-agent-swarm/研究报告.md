## 一、项目概述

本文是一位独立开发者 **@elvissun (Elvis)** 的实战分享：他用 OpenClaw 作为编排层，指挥多个 Codex/Claude Code Agent 并行工作，实现了单日 94 次 commit、30 分钟 7 个 PR 的开发效率。

**核心理念**: 通过上下文实现专业化，而不是通过不同的模型。

> 上下文窗口是零和的——填满代码就没有空间放业务上下文，填满客户历史就没有空间放代码库。这就是为什么两层系统（编排层 + 执行层）有效。

---

## 二、核心架构：双层 Agent 系统

### 2.1 编排层（OpenClaw / Zoe）

负责：
- 持有所有业务上下文（客户数据、会议记录、历史决策、Obsidian 笔记）
- 为每个任务生成精确的 prompt，选择合适的模型
- 主动发现问题（扫描 Sentry 错误、git log、会议笔记）
- 监控 agent 进度，失败时分析原因并调整 prompt 重试
- 持有管理员 API 权限（如给客户充值）和生产数据库只读权限
- 通过 Telegram 通知主人

**关键洞察**: 编排者永远不写代码，只写 prompt。

### 2.2 执行层（Codex / Claude Code / Gemini）

负责：
- 读写代码库
- 运行测试和构建
- 提交代码和创建 PR
- 响应 code review 反馈

每个 agent 有自己独立的 worktree（隔离分支）和 tmux 会话。

## 三、8 步完整工作流

### 第 1 步：客户需求 → 与 Zoe 确定范围

1. 与客户通话 → 会议笔记自动同步到 Obsidian
2. 与 Zoe 讨论需求（无需重复解释背景）
3. Zoe 三件套：
   - 调用管理员 API 给客户充值
   - 从生产数据库拉取客户现有配置
   - 生成编码 agent，带着包含所有上下文的 prompt

### 第 2 步：生成 Agent

```bash
# 创建隔离 worktree + 生成 agent
git worktree add ../feat-custom-templates -b feat/custom-templates origin/main
cd ../feat-custom-templates && pnpm install

tmux new-session -d -s "codex-templates" \
  -c "/path/to/worktree" \
  "$HOME/.codex-agent/run-agent.sh templates gpt-5.3-codex high"
```

- Codex: `--model gpt-5.3-codex -c "model_reasoning_effort=high" --dangerously-bypass-approvals-and-sandbox`
- Claude Code: `claude --model claude-opus-4.5 --dangerously-skip-permissions -p`

任务通过 `.clawdbot/active-tasks.json` 跟踪。

### 第 3 步：循环监控（cron 每 10 分钟）

- 检查 tmux 会话是否存活
- 检查分支是否有未合并的 PR
- 通过 gh cli 检查 CI 状态
- CI 失败或有关键反馈时自动重启 agent（最多 3 次）
- 100% 确定性，非常省 token

### 第 4 步：Agent 创建 PR

完成的定义（让 agent 知道这很重要）：
- PR 已创建
- 分支已同步到 main（无合并冲突）
- CI 通过（lint、types、unit tests、E2E）
- Codex 审查通过
- Claude Code 审查通过
- Gemini 审查通过
- 包含截图（如果有 UI 变更）

### 第 5 步：自动化代码审查

三个 AI 模型协同审查 PR：

| 审查者 | 优势 | 特点 |
|--------|------|------|
| **Codex Reviewer** | 边界情况、逻辑错误、竞态条件 | 最彻底，误报率低 |
| **Gemini Code Assist** | 安全问题、可扩展性、具体修复方案 | 免费，非常有用 |
| **Claude Code Reviewer** | 验证其他审查者标记的问题 | 过于谨慎，通常跳过非 critical 项 |

### 第 6 步：自动化测试

CI 流水线：Lint → TypeScript → 单元测试 → E2E 测试 → Playwright（预览环境）

特殊规则：PR 改了 UI 必须在描述中包含截图，否则 CI 失败。

### 第 7 步：人工审查

收到 Telegram 通知 → 检查截图 → 5-10 分钟审查 → 合并。

很多 PR 不看代码就直接合并。

### 第 8 步：合并 + 清理

每日 cron 清理孤立的 worktree 和任务注册表。

## 四、三种 Agent 的选择策略

| Agent | 适用场景 | 理由 |
|-------|---------|------|
| **Codex** | 后端逻辑、复杂 bug、多文件重构、跨代码库推理 | 慢但彻底，90% 的任务用它 |
| **Claude Code** | 前端工作、git 操作 | 更快，权限问题少 |
| **Gemini** | 漂亮的 UI 设计 | 设计感强，先生成 HTML/CSS 规范，再交给 Claude Code 实现 |

Zoe 根据任务类型选择合适的 agent，并在它们之间传递输出。

## 五、Ralph Loop V2：自我改进循环

本质是改进版的 Ralph Loop（记忆 → 生成 → 评估 → 保存学习成果），但关键区别是：

- agent 失败时，Zoe 不只是用相同的 prompt 重新生成
- 她带着完整的业务上下文分析失败原因
- 在每次重试时写更好的 prompt

示例干预：
- Agent 上下文用完了？「只关注这三个文件。」
- Agent 走错方向了？「停。客户想要的是 X，不是 Y。」
- Agent 需要澄清？「这是客户的邮件。」

**主动找工作**：早上扫描 Sentry → 生成 agent 调查和修复；会议后扫描会议笔记 → 标记功能需求；晚上扫描 git log → 更新 changelog。

## 六、硬件瓶颈

每个 agent 需要自己的 worktree + node_modules + 独立编译进程。Mac Mini 16GB 最多跑 4-5 个 agent。作者购买 Mac Studio M4 Max 128GB（$3,500）来支撑系统。

## 七、关键数据

- 单日最高 94 次 commit（那天还开了 3 个客户会议）
- 平均每天约 50 次 commit
- 30 分钟内 7 个 PR
- 大多数功能需求当天交付
- 成本：Claude ~$100/月，Codex ~$90/月，从 $20 开始
- 系统几乎能一次性完成所有中小型任务，无需任何干预

## 八、对 agent-harness 的参考价值

### 8.1 OpenClaw 作为编排层

OpenClaw（GitHub 31.9 万星，超越 Linux 成为第一大开源项目）是一个开源、自托管的个人 AI Agent 框架，支持通过 Telegram/飞书等 IM 下发指令。

其 Skill 机制可以动态注入领域知识，支持多 Agent 并行执行，具备多层容错。

### 8.2 可复用的设计模式

1. **双层架构**：编排者（持有业务上下文）+ 执行者（专注于代码），通过上下文专业化而非模型专业化
2. **worktree 隔离**：每个任务独立分支，互不干扰
3. **tmux 管理**：会话化运行 agent，支持中途干预（send-keys 重定向）
4. **自动化审查流水线**：多模型协同 review，分工明确
5. **cron 监控循环**：每 10 分钟自动检查 agent 状态
6. **完成标准定义**：让 agent 知道什么才算"完成"
7. **Telegram 通知**：状态变更推送给主人

### 8.3 迁移到 Claude Code 的可能性

本文使用 Codex 作为主力，但所有模式均可迁移到 Claude Code：

```bash
# 替代 codex，启动 Claude Code agent
claude --model claude-opus-4.5 --dangerously-skip-permissions -p "prompt here"
```

结合 OpenClaw 的编排能力，可以构建类似的"一人开发团队"系统。

### 8.4 内存是瓶颈

大规模多 Agent 并行受限于物理内存，128GB+ Mac Studio 是推荐配置。
