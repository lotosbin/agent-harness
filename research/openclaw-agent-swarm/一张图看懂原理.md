## 设计原则总结

| 原则 | 说明 | 效果 |
|------|------|------|
| **上下文专业化** | 编排者持有业务上下文，执行者只关注代码 | 上下文窗口零和问题的最优解 |
| **隔离执行** | 每个 agent 独立 worktree + tmux | 无合并冲突，可独立干预 |
| **自动监控** | cron 每 10 分钟检查状态 | 无人值守，失败自动恢复 |
| **多模型协同** | 不同模型负责不同审查维度 | 覆盖全面，误报低 |
| **完成标准明确** | 让 agent 知道什么才算"完成" | 自动化程度高，人工介入少 |
| **Telegram 通知** | 状态变更实时推送 | 主人保持完全控制 |
| **内存感知** | 限制并发 agent 数量 | 避免交换影响性能 |
