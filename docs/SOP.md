# 调研 SOP（Standard Operating Procedure）

> 本 SOP 定义了调研工作的标准流程。每个研究项目遵循此流程，确保输出质量一致。

---

## 调研步骤

研究一个专项目录时，按以下步骤进行：

### 1. 收集资料

- 主流媒体的相关资讯
- 官方网站和开源社区

### 2. 编写研究报告

结构：**因果体用 + 洞见**

- 因：项目背景、为什么存在
- 果：解决了什么问题、达到了什么效果
- 体：整体架构、核心组件
- 用：如何使用、集成方式
- 洞见：关键洞察、竞品对比、趋势分析

### 3. 编写入门指导

快速上手指南，包含：

- 环境要求
- 安装方法（推荐方式优先）
- 认证/配置
- 快速示例（覆盖主要能力）
- 常见问题

### 4. 编写一张图看懂使用

可视化速查图，涵盖：

- 安装命令（一行搞定）
- 核心命令速查
- 使用场景对照
- Agent 专享模式（如有）
- 配置与故障排除

### 5. 编写一张图看懂原理

架构图解，包含：

- 整体架构图
- 核心模块详解
- 关键技术设计
- 设计原则总结

---

## 输出文件结构

每个研究项目输出以下文件：

```
docs/<项目名>-research/
├── 研究报告.md       # 深度分析报告
├── 入门指导.md       # 快速上手指南
├── 一张图看懂使用.md  # 可视化速查（使用层面）
└── 一张图看懂原理.md  # 可视化速查（原理层面）
```

**注意**：CLAUDE.md 仅供 Agent 运行时参考，不作为产出文件的一部分。

## Stokowski 工作流补充

在 [stokowski](https://github.com/lotosbin/stokowski) 中运行时，调研完成后的步骤有所不同：

1. 研究完成后，使用 `gh issue comment <issue-id>` 将调研结论以 **Markdown 格式**更新到 Linear Issue
2. 评论内容应包含：
   - 调研结论摘要
   - 相关文件路径（使用 `[文件名](fleet-file://...)` 格式）
   - 任何需要人工确认的问题
3. 在 Linear Issue 的工作区（Workpad）中更新当前状态和决策记录

> 注：此补充规则仅适用于 stokowski 工作流；普通 git 工作流按 Git 规范执行。

## 命名规范

- 文件名：中文，直观表达内容
- 标题：简洁，不超过 20 字
- 引用路径：Markdown 链接，标注文件位置

---

## 质量标准

- 引用来源须标注链接
- 代码示例须验证正确性
- 图表须清晰可读
- 术语使用须一致
